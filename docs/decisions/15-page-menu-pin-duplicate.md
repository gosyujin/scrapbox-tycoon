# 15. ページ操作を本家 Scrapbox の配置に合わせ、pin と複製を追加した

## 経緯

本家 Scrapbox は、ページカードの右外側に縦のアイコン列 (ページ情報 / ページメニュー / ランダム) を置く。
ピン留め・複製・削除はページメニュー (ドキュメントのアイコン) の中。tycoon は 🔀 が画面上部のバー、
「このページを削除」がページ下部のボタンで、配置が違った。ピン留めと複製は無かった。
(本家の編集メニューの項目と並びは、閲覧専用ページでは確認できなかったので、既知の知識に基づく。)

## 配置

- `renderPage` / `renderReferencePage` の `.page-frame` 内に `.page-tools` (`pageToolsHtml()`)。
  PC (幅 960px 以上) はカードの右外側に縦、それ未満 (スマホ) はカード上端の右に横並び (`css/style.css`)。
- ページメニュー (保存済みのノートページのみ): ピン留めする/外す・ページを複製・ページを削除。
  参照ページと新規ページはランダムだけ。ページ画面の上部バーからは 🔀 を外した (一覧系の画面は従来どおり上部バー)。
- ボタンの `mousedown` は `preventDefault` する (押してもエディタが blur = commit しない)。
  どの項目も、必要なら自分で保存を済ませてから動く (複製は `shortcuts.leave()` で保存後に実行)。
- 削除は従来の確認ダイアログと `pageDeleted` ガード (閉じる途中の blur で保存し直さない) をそのまま使う。
  編集中に削除しても復活しないことをブラウザで確認済み。

## pin は端末ローカル (`src/pins.ts`)

pin を Page レコードに持たせると、同期層 (`isNoopSave`、pull の「内容同一は競合でない」判定、3-way マージ、
push の CAS) が pin を知る必要があり、`updated` の扱い (pin の切替で進めるか) も決める必要がある。
内容ではない状態のために CLAUDE.md の注意領域に踏み込むのは割に合わないので、`localStorage`
(`scrapbox_tycoon_pins_v1`、キーは小文字タイトル → ピン留めした時刻) にだけ持つ。**端末ごとに別々の pin になる。**
- 一覧では pin 済みを先頭 (新しく留めた順) に出し、カードに 📌 を付ける。その中・外とも、選んだ並び順は保つ。
- リネームでは pin が付いてくる (`rename`)、削除・マージ・競合コピー削除では外す (`unpin`)。他端末での削除で
  残った pin は、存在しないタイトルなので何も起きない (表示されない)。
- 同期したい場合は後から足せる (Page フィールドか別ファイル)。その場合は上記の同期層の項目が要る。

## 複製

`<title> (copy)` (あれば `_2`, `_3` ...) として本文と `lineTimes` をそのまま保存し、そのページを開く。
本家の複製のタイトル規則は確認できていないので、これは tycoon 側の決め。

## キー操作との関係 (decisions/14)

ハンドラ `pin` / `dup` / `del` を追加。UserScript の `alt+p` = pin に合わせて edit の既定に `alt+p` を割り当てた。
`dup` / `del` は UserScript が表で割り当てたときに使う (UserScript 側では定義のみで未割り当て)。
保存済みのノートページが画面に無いとき (一覧・参照・新規ページ) はキーを握りつぶさない。

## ランダムの対象

従来どおり参照プロジェクトのみ (位置だけ本家に合わせた)。
